# Release Checklist

## Prepare

1. Update `CHANGELOG.md`: move `[Unreleased]` changes to a new versioned section.
2. Run `swift test` — all tests must pass.
3. Build and package the app:
   ```bash
   bash scripts/package_macos_app.sh <version>
   ```
4. Verify the generated bundle at `dist/SwiftOrganizerX.app`.
5. Verify the zip archive at `dist/SwiftOrganizerX-<version>-macos.zip`.
6. Launch the `.app` and confirm:
   - File Organizer: select a directory and organize files.
   - Undo: verify files are restored.
   - Clean Empty: confirm dialog appears; verify empty folders are removed.
   - Storage Insights: select a directory and verify Pareto analysis.
   - Notes Assistant: fetch notes (macOS will prompt for Automation permission — grant it); verify notes appear.
   - Settings: save and reload an API key.

## Privacy & Permissions

- **Apple Events / Automation**: The app sends Apple Events to Notes.app via `NSAppleScript`. macOS will prompt the user for Automation permission on first use. The `NSAppleEventsUsageDescription` key in `Info.plist` (generated by `package_macos_app.sh`) provides the usage description shown to the user.
- **OpenAI API Key**: Stored in the macOS Keychain. Never stored in `UserDefaults` after initial migration.
- **AI Consent**: The app requires explicit user consent before sending note data to OpenAI. Consent can be revoked at any time in Settings.

## Code Signing & Notarization

The packaging script uses ad-hoc signing (`codesign --sign -`) by default. This is suitable for internal or trusted distribution only.

For public distribution:

1. Configure the `sign-and-notarize` job in `.github/workflows/ci.yml` (currently commented out) by adding the required secrets:
   - `DEVELOPER_ID_APPLICATION_CERT` — base64-encoded `.p12` Developer ID Application certificate
   - `DEVELOPER_ID_CERT_PASSWORD` — password for the `.p12`
   - `APPLE_ID` — Apple ID email for notarization
   - `APPLE_ID_PASSWORD` — app-specific password
   - `APPLE_TEAM_ID` — 10-character Apple Developer Team ID
2. Update `package_macos_app.sh` to accept a signing identity and replace the ad-hoc `codesign --sign -` call with:
   ```bash
   codesign --force --deep \
     --sign "Developer ID Application: Your Name ($APPLE_TEAM_ID)" \
     --options runtime \
     "$APP_BUNDLE"
   ```
3. Notarize via `xcrun notarytool submit` and staple the ticket.

## App Icon

The app currently ships without an icon. To add one:

1. Wrap the package in an Xcode project.
2. Add an `AppIcon` asset catalog to the app target at `Resources/Assets.xcassets/AppIcon.appiconset/`.
3. Provide a 1024×1024 source PNG; Xcode generates all required sizes.

## Tag

1. Commit all release changes.
2. Create an annotated tag:
   ```bash
   git tag -a v1.1.0 -m "SwiftOrganizerX v1.1.0"
   git push origin v1.1.0
   ```

## Publish

1. Create a GitHub release from the tag.
2. Upload `dist/SwiftOrganizerX-<version>-macos.zip` as the binary asset.
3. Copy the relevant section from `CHANGELOG.md` as release notes.
4. List known limitations (see `README.md`).

## Known Limitations at Launch

- No app icon (SPM limitation; Xcode project wrapper required).
- Ad-hoc signing only (not suitable for Gatekeeper-cleared distribution without Developer ID + notarization).
- Undo state is session-only (lost on quit).
- Notes automation requires user to grant Automation permission on first use.
